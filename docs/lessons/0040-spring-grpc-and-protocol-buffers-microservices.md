# 0040: Microservice RPC with Spring gRPC and Protocol Buffers

In high-throughput microservice architectures, using REST with text-based JSON over HTTP/1.1 introduces significant latency, heavy CPU serialization overhead, and network bandwidth waste.

**gRPC** (developed by Google) is a high-performance, open-source Remote Procedure Call (RPC) framework built on **HTTP/2 multiplexing** and **Protocol Buffers (Protobuf)** binary serialization.

In this lesson, you will master defining `.proto` service contracts, compiling Java stubs, implementing gRPC server services with `@GrpcService`, consuming remote stubs via `@GrpcClient`, and streaming binary messages over HTTP/2.

## 2. Defining contracts: `order_service.proto`

Place Protocol Buffer definitions inside `src/main/proto/order_service.proto`:

```protobuf
syntax = "proto3";

package com.example.grpc;

option java_multiple_files = true;
option java_package = "com.example.grpc.stubs";
option java_outer_classname = "OrderServiceProto";

// 1. Service Definition
service OrderGrpcService {
    // Unary RPC: Single request -> Single response
    rpc GetOrderById (OrderRequest) returns (OrderResponse);
    
    // Server Streaming RPC: Single request -> Continuous binary stream
    rpc StreamOrderTrack (OrderRequest) returns (stream OrderStatusUpdate);
}

// 2. Message Structures
message OrderRequest {
    int64 order_id = 1;
}

message OrderResponse {
    int64 order_id = 1;
    string order_number = 2;
    double total_amount = 3;
    string status = 4;
    int64 customer_id = 5;
}

message OrderStatusUpdate {
    int64 order_id = 1;
    string current_status = 2;
    string location = 3;
    string timestamp = 4;
}
```

## 3. Implementing the gRPC server (`@grpcservice`)

Spring Boot exposes gRPC services using the `@GrpcService` annotation, extending the abstract base class generated by `protoc`:

### `OrderGrpcServiceImpl.java`
```java
package com.example.grpc.service;

import com.example.grpc.stubs.OrderGrpcServiceGrpc;
import com.example.grpc.stubs.OrderRequest;
import com.example.grpc.stubs.OrderResponse;
import com.example.grpc.stubs.OrderStatusUpdate;
import io.grpc.Status;
import io.grpc.stub.StreamObserver;
import net.devh.boot.grpc.server.service.GrpcService;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

@GrpcService
public class OrderGrpcServiceImpl extends OrderGrpcServiceGrpc.OrderGrpcServiceImplBase {

    private static final Logger log = LoggerFactory.getLogger(OrderGrpcServiceImpl.class);

    @Override
    public void getOrderById(OrderRequest request, StreamObserver<OrderResponse> responseObserver) {
        long orderId = request.getOrderId();
        log.info("Received gRPC request for Order ID: {}", orderId);

        if (orderId <= 0) {
            // Return standard gRPC Status Error
            responseObserver.onError(
                Status.INVALID_ARGUMENT
                    .withDescription("Order ID must be a positive integer")
                    .asRuntimeException()
            );
            return;
        }

        // Construct Protobuf binary response
        OrderResponse response = OrderResponse.newBuilder()
                .setOrderId(orderId)
                .setOrderNumber("ORD-" + orderId)
                .setTotalAmount(149.99)
                .setStatus("PAID")
                .setCustomerId(101L)
                .build();

        // Send payload and complete the RPC stream
        responseObserver.onNext(response);
        responseObserver.onCompleted();
    }

    @Override
    public void streamOrderTrack(OrderRequest request, StreamObserver<OrderStatusUpdate> responseObserver) {
        long orderId = request.getOrderId();

        // Stream real-time status updates to client over HTTP/2
        String[] statuses = {"ORDER_PLACED", "PAYMENT_CONFIRMED", "WAREHOUSE_DISPATCHED", "DELIVERED"};
        for (String status : statuses) {
            OrderStatusUpdate update = OrderStatusUpdate.newBuilder()
                    .setOrderId(orderId)
                    .setCurrentStatus(status)
                    .setLocation("Distribution Center Alpha")
                    .setTimestamp(java.time.Instant.now().toString())
                    .build();

            responseObserver.onNext(update);
        }
        responseObserver.onCompleted();
    }
}
```

## 4. Consuming gRPC with `@GrpcClient`

In client microservices, inject auto-configured blocking or reactive stubs:

```java
package com.example.grpc.client;

import com.example.grpc.stubs.OrderGrpcServiceGrpc.OrderGrpcServiceBlockingStub;
import com.example.grpc.stubs.OrderRequest;
import com.example.grpc.stubs.OrderResponse;
import net.devh.boot.grpc.client.inject.GrpcClient;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

@Service
public class OrderServiceClient {

    // Auto-wires ManagedChannel configured in application.yml
    @GrpcClient("order-service")
    private OrderGrpcServiceBlockingStub orderStub;

    public OrderResponse fetchOrder(long orderId) {
        // Enforce 2-second timeout deadline
        OrderRequest request = OrderRequest.newBuilder().setOrderId(orderId).build();
        return orderStub.withDeadlineAfter(2, TimeUnit.SECONDS).getOrderById(request);
    }
}
```

### Client configuration (`applicationyml`)
```yaml
grpc:
  server:
    port: 9090 # gRPC Netty server listener port
  client:
    order-service:
      address: 'static://localhost:9090'
      negotiation-type: plaintext # or 'tls' for production mTLS
```

## 5. Spring Boot 3 vs Spring Boot 4: gRPC architecture evolution

``` mermaid
flowchart TD
    subgraph SB3["Spring Boot 3.x (Community Starters)"]
        ThirdPartyStarter["net.devh:grpc-spring-boot-starter"]
        NettyServer["Dedicated Netty gRPC Port (:9090)"]
        ManualProtoc["Manual Maven protobuf-maven-plugin Tooling"]
    end

    subgraph SB4["Spring Boot 4.x (Official Spring gRPC)"]
        OfficialStarter["Official spring-boot-starter-grpc (Spring 7 Native)"]
        UnifiedTomcatHTTP2["Single Port HTTP/2 Dispatch (Tomcat 11 / HTTP/3)"]
        LoomGrpcChannels["Virtual Thread Native Managed Channels"]
    end

    SB3 ==>|First-Class Framework Integration| SB4
```

### Key differences and configuration comparison

| gRPC Feature | Spring Boot 3.x | Spring Boot 4.x |
| :--- | :--- | :--- |
| **Starter Ecosystem** | Required community `grpc-spring-boot-starter` or `yidongnan`. | **Official `spring-boot-starter-grpc`**: Maintained directly by the Spring Core team. |
| **Port Multiplexing** | Required two separate server ports (8080 for REST/Actuator, 9090 for gRPC). | **Unified Port Binding**: Shares standard HTTP/2 / HTTP/3 port (8080) for REST and gRPC. |
| **Thread Scaling** | Bound by Netty boss/worker event loop thread groups. | **Project Loom Virtual Threads**: Client and server RPC invocations run on lightweight Loom threads. |

## 7. Knowledge check and practice

??? question "Question 1: Why does gRPC achieve significantly higher throughput and lower latency than traditional REST over JSON?"
    **Answer**: gRPC uses compact binary Protocol Buffers (eliminating string parsing overhead) and runs over HTTP/2, which supports multiplexed concurrent streams over a single TCP connection.

??? question "Question 2: What is the purpose of field numbers (e.g. `int64 order_id = 1;`) in `.proto` message definitions?"
    **Answer**: Field numbers identify fields in the binary encoding format; they must never be changed once a message is deployed to maintain backward and forward compatibility.

??? question "Question 3: What is the difference between a Unary RPC and a Server-Streaming RPC?"
    **Answer**: A Unary RPC sends a single request and returns a single response; a Server-Streaming RPC sends a single request and returns a continuous stream of binary messages until completed.
