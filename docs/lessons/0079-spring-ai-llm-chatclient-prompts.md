# 0079: Spring AI: LLM Chat Clients, prompts, and multi-model integration

In modern enterprise software, integrating Large Language Models (LLMs) into backend services is becoming standard for customer support bots, intelligent search, automated code review, and semantic data extraction.

Writing custom Python microservices or ad-hoc HTTP clients for every LLM vendor creates vendor lock-in and brittle maintenance. **Spring AI** is an official Spring framework project that provides a unified, portable abstraction layer for Generative AI across OpenAI, Anthropic Claude, Google Gemini, Ollama (Local LLMs), AWS Bedrock, and Azure OpenAI.

In this lesson, you will master the fluent `ChatClient` API, dynamic `PromptTemplate` variables, Structured Output parsing with `BeanOutputConverter`, and streaming tokens reactively using WebFlux.

## 3. The fluent `ChatClient` API

In Spring AI, `ChatClient` provides a fluent, expressive builder for crafting prompts, injecting system instructions, and retrieving results:

```java
package com.example.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;

@Service
public class AssistantService {

    private final ChatClient chatClient;

    public AssistantService(ChatClient.Builder chatClientBuilder) {
        this.chatClient = chatClientBuilder
                .defaultSystem("You are a helpful, concise enterprise customer support agent for AcmeCorp.")
                .build();
    }

    /**
     * 1. Synchronous LLM Generation
     */
    public String askAssistant(String userMessage) {
        return chatClient.prompt()
                .user(userMessage)
                .call()
                .content();
    }

    /**
     * 2. Real-Time Token Streaming with Project Reactor Flux
     */
    public Flux<String> streamAssistantResponse(String userMessage) {
        return chatClient.prompt()
                .user(userMessage)
                .stream()
                .content(); // Emits tokens as they are generated by the LLM
    }
}
```

## 4. Dynamic prompt templates parameter injection

Never concatenate raw strings into prompts. Use `PromptTemplate` to prevent prompt injection and structure context:

```java
package com.example.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.stereotype.Service;

import java.util.Map;

@Service
public class CodeReviewService {

    private final ChatClient chatClient;

    public CodeReviewService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String reviewJavaCode(String codeSnippet, String languageLevel) {
        String templateString = """
            Review the following {language} code for security vulnerabilities, memory leaks, and concurrency bugs:
            
            ```java
            {code}
            ```
            
            Provide recommendations formatted in Markdown with code diffs.
            """;

        PromptTemplate template = new PromptTemplate(templateString);
        var prompt = template.create(Map.of(
                "language", languageLevel,
                "code", codeSnippet
        ));

        return chatClient.prompt(prompt).call().content();
    }
}
```

## 5. Structured output parsing (`beanoutputconverter`)

LLMs naturally return unstructured natural language strings. In production microservices, you need typed JSON mapped directly into Java records:

```java
package com.example.dto;

public record SentimentAnalysisResult(
        String sentiment,       // POSITIVE, NEUTRAL, NEGATIVE
        double confidenceScore, // 0.0 to 1.0
        String primaryEmotion,
        String summaryReason
) {}
```

```java
package com.example.service;

import com.example.dto.SentimentAnalysisResult;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.converter.BeanOutputConverter;
import org.springframework.stereotype.Service;

@Service
public class SentimentAnalysisService {

    private final ChatClient chatClient;

    public SentimentAnalysisService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public SentimentAnalysisResult analyzeReview(String customerReviewText) {
        var outputConverter = new BeanOutputConverter<>(SentimentAnalysisResult.class);

        return chatClient.prompt()
                .user(u -> u.text("""
                        Analyze the sentiment of the following customer feedback:
                        "{feedback}"
                        
                        {format}
                        """)
                        .param("feedback", customerReviewText)
                        .param("format", outputConverter.getFormat())) // Automatically injects JSON Schema instructions
                .call()
                .entity(outputConverter); // Automatically deserializes LLM JSON into Java Record!
    }
}
```

## 8. Knowledge check and practice

??? question "Question 1: What is the main advantage of Spring AI's `ChatClient` over direct REST calls to OpenAI or Anthropic?"
    **Answer**: It provides a unified, portable Java API that allows switching between OpenAI, Gemini, Claude, and local Ollama models by changing only configuration properties.

??? question "Question 2: How does `BeanOutputConverter` enforce structured JSON responses from an LLM?"
    **Answer**: It generates a JSON Schema from a Java class/record, injects format instructions into the prompt, and automatically deserializes the LLM's response into a typed Java object.

??? question "Question 3: How do you stream tokens reactively from Spring AI to a WebFlux endpoint?"
    **Answer**: By invoking `.stream().content()` on the `ChatClient` prompt chain, which returns a Project Reactor `Flux<String>` emitting tokens as they are generated.
