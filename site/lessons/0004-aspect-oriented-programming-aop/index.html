0004: Aspect-Oriented Programming (AOP) & Advice Types¶

In enterprise applications, certain concerns span across multiple architectural layers: performance metric collection, transaction boundaries, audit trails, and security checks. These are known as Cross-Cutting Concerns.

Without Aspect-Oriented Programming (AOP), you would have to duplicate code in every single service method. In this lesson, we master Spring AOP, explore the 5 Advice types, and demystify Proxy mechanics and the Self-Invocation trap.

1. Core AOP Concepts Demystified¶

    subgraph Request_Pipeline["Method Execution Pipeline"]
        direction LR
        Caller["Controller / Caller"] --> Proxy["Spring AOP Proxy<br/><i>(Aspect Advice)</i>"]
        Proxy --> Target["Target Service Bean<br/><i>(Business Logic)</i>"]
    end
Term Simple Definition Concrete Example
Aspect A modular class encapsulating a cross-cutting concern LoggingAspect, SecurityAspect
Join Point A specific point in program execution (In Spring: method execution) Executing orderService.createOrder()
Pointcut A predicate expression matching target Join Points @annotation(TrackExecutionTime)
Advice The code executed at a matched Join Point Logging start time before method runs
Target Object Your raw business object being advised The actual OrderServiceImpl instance
AOP Proxy The wrapper generated by Spring (CGLIB or JDK Dynamic Proxy) Intercepts calls and delegates to Advice + Target

2. The 5 Advice Types¶

Spring AOP provides 5 advice types ordered by their execution point:

sequenceDiagram
    autonumber
    actor C as Caller
    participant P as Spring AOP Proxy
    participant T as Target Method

    C->>P: Call method()
    Note over P: 1. @Before advice executes
    alt Success Path
        P->>T: Proceed to Target Method
        T-->>P: Returns Result
        Note over P: 2. @AfterReturning advice executes
    else Exception Thrown
        P->>T: Proceed to Target Method
        T--xP: Throws Exception
        Note over P: 3. @AfterThrowing advice executes
    end
    Note over P: 4. @After (finally) advice executes
    Note over P: 5. @Around wraps the ENTIRE sequence above!
    P-->>C: Returns Response to Caller

3. Hands-On: Building a Custom @TrackLatency Aspect¶

Let's build a production-grade latency monitoring aspect using custom annotations and @Around advice.

Step 1: Create Custom Annotation¶

package com.example.annotation;

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface TrackLatency {
    String value() default "";
}

Step 2: Write the Aspect Class with @Around Advice¶

package com.example.aspect;

import com.example.annotation.TrackLatency;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;

@Aspect
@Component
public class PerformanceMonitoringAspect {

    private static final Logger log = LoggerFactory.getLogger(PerformanceMonitoringAspect.class);

    // Matches any method annotated with @TrackLatency
    @Around("@annotation(trackLatency)")
    public Object measureExecutionTime(ProceedingJoinPoint joinPoint, TrackLatency trackLatency) throws Throwable {
        String methodName = joinPoint.getSignature().toShortString();
        String metricName = trackLatency.value().isEmpty() ? methodName : trackLatency.value();

        long startTime = System.currentTimeMillis();
        try {
            // Proceed to execute the actual target method
            Object result = joinPoint.proceed();
            return result;
        } finally {
            long duration = System.currentTimeMillis() - startTime;
            log.info("Metric [{}] executed in {} ms", metricName, duration);
        }
    }
}

Step 3: Use the Annotation in Your Service¶

@Service
public class PaymentService {

    @TrackLatency("payment-gateway-charge")
    public PaymentResponse processPayment(PaymentRequest request) {
        // Business logic here...
        return new PaymentResponse("SUCCESS");
    }
}

4. Other Advice Examples (@Before, @AfterThrowing)¶

@Aspect
@Component
public class AuditAspect {

    private static final Logger log = LoggerFactory.getLogger(AuditAspect.class);

    // Matches all methods in com.example.service package
    @Before("execution(* com.example.service..*(..))")
    public void logMethodEntry(JoinPoint joinPoint) {
        log.info("Entering method: {}", joinPoint.getSignature().toShortString());
    }

    // Intercepts exceptions thrown by services
    @AfterThrowing(pointcut = "execution(* com.example.service..*(..))", throwing = "ex")
    public void logException(JoinPoint joinPoint, Exception ex) {
        log.error("Exception in {} with error: {}", joinPoint.getSignature().toShortString(), ex.getMessage());
    }
}

5. Critical Architecture Trap: The Self-Invocation Problem¶

One of the most frequent senior interview questions and production bugs is the Spring AOP Self-Invocation Pitfall.

flowchart TD
    subgraph ScenarioA["External Call (Works Correctly)"]
        ClientA[Controller] --> ProxyA[Spring AOP Proxy]
        ProxyA -->|Advice Triggered!| TargetA[OrderService.processOrder]
    end

    subgraph ScenarioB["Internal Self-Invocation (Proxy Bypassed!)"]
        ClientB[Controller] --> ProxyB[Spring AOP Proxy]
        ProxyB --> TargetB[OrderService.processOrder]
        TargetB -->|Direct 'this' Call| Inner[OrderService.saveAuditLog]
        style Inner stroke:#f44,stroke-width:2px;
        noteInner["❌ Proxy is Bypassed!<br/>@Transactional / @TrackLatency on saveAuditLog will NOT run!"]
    end

Why it happens:¶

When processOrder() calls this.saveAuditLog(), it is executing directly on the raw Java object (this), completely bypassing the Spring AOP Proxy wrapper.

How to resolve:¶

  1. Refactor into a separate bean: Move saveAuditLog() into an AuditService bean and inject it.
  2. Self-Injection: Inject OrderService into itself with @Lazy.

7. Knowledge Check & Retrieval Practice¶

Question 1: Which Advice type provides complete control over target method execution and return values?

Answer: The @Around advice wraps execution completely, controlling when to proceed, modify outputs, or catch exceptions.

Question 2: Why does @Transactional or @TrackLatency fail to trigger when called internally from another method in the same class?

Answer: Direct internal method calls use this, which invokes the raw target instance directly and bypasses the proxy wrapper.

Question 3: What is the key difference between @After and @AfterReturning advice?

Answer: @AfterReturning executes only upon successful method completion, whereas @After executes unconditionally like a finally block.
